# Install

Requirements for everything below: **Node.js 18+** and npm. Optional: [Rojo](https://rojo.space) for live sync into Studio.

- Windows: `winget install OpenJS.NodeJS.LTS` (or the installer from [nodejs.org](https://nodejs.org)), then open a new terminal.
- macOS: `brew install node` (or nodejs.org). Linux: your package manager or nodejs.org.

Check your setup any time with `node install.mjs --doctor` (or `install.cmd --doctor` on Windows). It shows your OS, Node, npm, Rojo, and, when you pass a project folder (`node skills/wayzoo/scripts/wayzoo.mjs doctor my-game`), whether `default.project.json` is ready for Rojo sync.

## Pick your environment

| Where you use Claude | OS | How to install | Rojo live sync |
|---|---|---|---|
| Claude Desktop app (UI) | Windows, macOS | Import `dist/wayzoo.skill` in Customize > Skills | No: Claude hands you the changed files |
| Claude in the browser | Any | Same as the Desktop app | No: same as above |
| Claude Code CLI | Windows, macOS, Linux | `node install.mjs --claude-code` | Yes: Claude works in your project folder |

## 1. Claude Desktop UI (Windows / macOS) and claude.ai

The skill is one ZIP file, `dist/wayzoo.skill`, generated by `node install.mjs`. The steps are the same in the Windows and macOS desktop apps and in the browser.

**Generate the file**

```
node install.mjs
```

On Windows you can also double-click `install.cmd` (or run `.\install.ps1` in PowerShell). It prints `OK built ...\dist\wayzoo.skill`. Add `--open` to show the file in Explorer / Finder. A prebuilt `dist/wayzoo.skill` is also in the repo if you do not want to run anything.

**Import it into Claude**

1. Open the Claude Desktop app (or claude.ai).
2. Go to **Customize > Skills**.
3. Click **+**, then **Create skill > Upload a skill**, and pick `dist/wayzoo.skill`.
4. Switch the skill on.
5. Make sure code execution / file creation is enabled in your Claude settings (Settings > Capabilities; on Team and Enterprise plans an owner may need to enable it).
6. Ask Claude: "write my Roblox code in TypeScript".

In a chat, the project lives in Claude's own workspace: Claude builds there and hands you the changed files, which you drop into your Rojo project. If you want Rojo to pick up every build automatically, use Claude Code (below) or a connected local folder instead.

## 2. Claude Code CLI (automatic deployment)

```
node install.mjs --claude-code            # personal: ~/.claude/skills/wayzoo
node install.mjs --claude-code --project  # this project only: ./.claude/skills/wayzoo
```

This copies `skills/wayzoo` into Claude Code's skills folder, replacing any older copy, so the same command also upgrades. On Windows the personal folder is `%USERPROFILE%\.claude\skills\wayzoo`; `install.cmd --claude-code` works too. Restart Claude Code, or run `/skills`, to see it. If you are signed in with the same account, skills uploaded in step 1 also sync to Claude Code.

With Claude Code, Claude works directly in your project folder: run `rojo serve` once, connect the Studio plugin, and every `build` lands in Studio with no code passing through the chat.

**Optional: Roblox Studio MCP.** If you also connect a Roblox Studio MCP server, the skill uses it only for live telemetry (Output window, instance inspection during playtests). Your TypeScript files stay the source of truth.

## 3. Windows, native (no WSL, no Git Bash, no Bash)

Everything is Node, so cmd and PowerShell both work.

```
git clone https://github.com/wayzoo/wayzoo-skill.git
cd wayzoo-skill
install.cmd
.\wayzoo.cmd doctor
.\wayzoo.cmd setup my-game
.\wayzoo.cmd build my-game
.\wayzoo.cmd deps my-game
cd my-game
rojo serve
```

- `install.cmd` is double-click friendly. `install.ps1` does the same from PowerShell; if scripts are blocked run `powershell -ExecutionPolicy Bypass -File .\install.ps1`.
- Without the `.cmd` launcher you can always call `node skills\wayzoo\scripts\wayzoo.mjs <command>`.
- Paths with spaces are fine; put them in quotes.

## 4. macOS / Linux, plain scripts

```
git clone https://github.com/wayzoo/wayzoo-skill.git
cd wayzoo-skill
node skills/wayzoo/scripts/wayzoo.mjs setup my-game
node skills/wayzoo/scripts/wayzoo.mjs build my-game
cd my-game && rojo serve
```

`skills/wayzoo/scripts/setup.sh`, `build.sh` and `inspect-deps.sh` still work; they only call the Node scripts.

## Commands

| Command | What it does |
|---|---|
| `setup <dir>` | Creates a roblox-ts project (server, client, shared) |
| `build <dir> [N]` | Compiles; prints one line, or the first N error lines (default 25), import errors first |
| `deps <dir>` | Lists installed `@rbxts` packages |
| `doctor [dir]` | Checks OS, Node, npm, Rojo, the project and its `default.project.json`, and the Windows entry points |
| `rojo serve` | Syncs `out/` into Studio |
| `node install.mjs` | Builds `dist/wayzoo.skill` and prints the upload steps |
| `node tools/test.mjs` | Offline smoke tests |
| `node benchmarks/measure.mjs` | Reproduces the token benchmark |

## Troubleshooting

- **"Node.js 18+ is required"**: install Node and open a new terminal so `node` is on your PATH.
- **Upload rejected in Claude**: use the file built by this repo (the folder inside is named `wayzoo`, with `SKILL.md` in it). Rebuild it with `node install.mjs`.
- **Skill can't run code**: enable code execution / file creation in Claude's settings.
- **Windows, `npm` not found**: reinstall Node with the "Add to PATH" option, then reopen the terminal.
- **`doctor` says `default.project.json` is missing**: run `wayzoo setup <dir>` in a new folder, or create it with `rojo init`. An old `rojo.json` (Rojo 0.5) is not read by current Rojo.

## Upgrade

Pull the repo and re-upload `dist/wayzoo.skill` (Customize > Skills), or rerun `node install.mjs --claude-code`.
